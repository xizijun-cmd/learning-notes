# 为什么 DSH 值得单独写一本书

Agent = Model + Harness。模型出主意，Harness 跑腿，把"说"变成"做"。等式很简单，但这几年大家只研究等式左边，右边那层一直是黑盒。

说个我自己的体验。每天用的 WorkBuddy，模型可以换 Kimi 也可以换 DeepSeek，但读文件、跑命令、改代码这些动手的活，全是 WorkBuddy 这个 Harness 在干。模型换来换去，活照样干得完——拉开 Agent 体验差距的，不只在模型，更在这层"身体"。可这一层，多数产品都当私房经验：要么闭源，要么开源了也没人逐章拆给你看。DSH 不但开源，还开源到了运行机制这一层。单凭这一点，就值得写一本书。

它彻底在哪？不是多给你几个 Tool，那只是在工具圈里做加法。DSH 公开的是组织方式：从工具调度、拦截，到 Loop 控制、结果处理、失败兜底，全开放。模型适配、工具注册、会话记录、Agent Loop 这些产品能力都进了插件体系，想扩展不用去改特权核心。但一切皆插件不等于没有核心：核心不管具体活，只管组件怎么组合、怎么退出。就像电源插座：统一的是怎么插，不管插上来的是台灯还是风扇。机制是 Harness 的，能力是插件的。

还有一点。书必须写稳定的东西，没人会给下个月就过时的 API 写书。DSH 里越靠近组织方式越稳定，越靠近具体实现越易变。它敢彻底开源，开源的又恰好是稳定的那部分，所以值得被写成一本书。
